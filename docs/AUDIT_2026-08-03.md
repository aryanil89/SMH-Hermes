## Bottom line

The finalized architecture is well-researched — GenieX is real, the Qwen3-4B NPU bundles are
real, Hermes Agent is real, and every QUAD skill claim checks out against the local SDK. But the
plan contains **one demo-killing contradiction no doc notices**: Hermes Agent hard-requires ≥64K
context and rejects smaller models at startup, while every documented Hexagon NPU bundle ships
with a 4,096-token context. Two more load-bearing claims (tool-calling through `geniex serve`,
`quad-profile` working on LLM bundles) are unverified. The Arduino UNO Q spec line is wrong in
every particular.

### 1.5 Hardware targets

**Snapdragon X Elite laptop** — viable throughout: GenieX supports Windows ARM64 on Snapdragon X
(verified), AI Hub Qwen3-4B lists X Elite (verified). Bundles can't be *built* on the X Elite
(no win-arm64 torch) but run there — consistent with the plan's build-time framing.

**Galaxy S25 Ultra** — "Snapdragon 8 Elite for Galaxy" **VERIFIED** (all S25 models, all regions — no
Exynos split). `android-8elite` is a real QUAD target (Hexagon V79). Baseline role trivially fine.
Stretch caveats: separate per-chipset bundle; GenieX-on-Android means embedding an SDK in an app —
"same path as the laptop" understates the work.

**Arduino UNO Q** — QRB2210 identification **VERIFIED** (docs.arduino.cc: Dragonwing QRB2210 +
STM32U585; the QUAD SDK's own skill says "QCS2210" — naming mismatch worth reconciling). But
"**1 TOPS, 2GB RAM, INT8-only**" is **CONTRADICTED on all three counts** by Qualcomm's product
page/datasheet: **no NPU on QRB2210** ("AI models can run on the GPU and CPU"), no official TOPS
figure exists anywhere, the board ships in **2GB and 4GB** variants, and INT8-only is false
(Arduino's own guide runs Q4 GGUF models). "Confirmed too weak for **any** LLM inference" is
**CONTRADICTED** — Arduino officially demonstrates SmolLM2-135M and Llama-3.2-1B-Q4 on the board
(blog.arduino.cc, 2026-06-18). The *decision* not to put the agent's LLM there remains correct,
but "confirmed" claims a verification that never happened; the bogus specs trace to the QUAD SDK's
`quad-unoq` reference table, itself unsupported by Qualcomm primary docs. Also: the UNO Q has
**no onboard environmental sensors** — temperature/humidity/leak sensing requires external
hardware (Qwiic/Modulino/shield), which no doc mentions procuring.

**Update 2026-08-06** — the "AI models can run on the GPU and CPU" half of that Qualcomm quote
above went unactioned for three days: no doc named or probed the GPU. It's real — `vulkaninfo`
enumerates a `Turnip Adreno (TM) 702` device — and it's now been tried for the small on-device
activity-inference LLM this board runs (see [ONDEVICE_ACTIVITY.md](ONDEVICE_ACTIVITY.md)): measured
against CPU, it lost, crashing under repeated load and running ~32× slower on decode even when it
didn't. The *decision* not to put the **agent's** LLM here is still correct and unaffected; this is
about the much smaller model this board now runs on its own.

## Prioritized open risks

**P0 — Context-length contradiction (plan-breaking as written).** Hermes hard-rejects models
under 64K context at startup; every documented Genie/GenieX NPU bundle ships at 4,096 tokens. No
doc notices this. Options: (a) run Qwen3-4B-Instruct-2507 **GGUF via GenieX's llama.cpp path** at
64K+ (CPU/GPU — surrenders or hybridizes the "NPU-accelerated" pitch; llama.cpp's experimental
Hexagon backend on Windows-on-Snapdragon is a possible partial recovery); (b) attempt a custom AI
Hub export with `--context-length` above 4096 (undocumented territory, KV-cache memory limits);
(c) patch/bypass Hermes's context check and accept truncation (likely breaks its memory/skills
machinery — the reason the requirement exists). This must be the Day-1 spike, above the NPU
driver check.

**P1 — Tool calling through `geniex serve` on NPU bundles is unverified.** The demo's entire
premise is the agent driving MCP tools through an OpenAI-compatible API. The endpoint exists, but
no primary source shows OpenAI `tools`/function-calling working against NPU bundles, and an open
AI Hub issue (qualcomm/ai-hub-models#195) shows users still *requesting* it. If absent, a
template/parser shim is needed — the very shim the doc celebrates deleting. Verify with one curl
on Day 1.

**P2 — Benchmarking path (`quad-profile`/`quad-orchestrate` on an LLM bundle) is unverified.**
QUAD's own LLM work used a dedicated tok/s benchmark script instead. If the MCP profiling tools
don't accept Genie bundles, the benchmark slide changes shape (prefill/decode tok/s harness, not
P50/P95/P99 + allocation percentages). Cheap to discover — check early in Day 4 planning.

**P3 — UNO Q spec line and "confirmed" language is wrong (credibility risk, not schedule risk).**
Fix the specs (QRB2210: no NPU, GPU/CPU inference, 2GB or 4GB variants, no official TOPS), drop
"INT8-only" and "confirmed too weak for any LLM," and note that environmental sensing requires
**external** Qwiic/Modulino sensor hardware nobody has listed. Reconcile QRB2210 (docs, correct)
vs QCS2210 (QUAD SDK skill) naming.

**P4 — Staleness debt to re-check before the pitch.** GenieX is a June-2026 Developer Preview
moving weekly; Hermes just switched to Node 26 (2026-08-02) and its Windows story flipped from
WSL2 to native ARM64 (~May 2026) — update FEASIBILITY §Hermes accordingly; NexaAI NPU bundles are
CC BY-NC (fine for a hackathon, not beyond); the phone stretch goal needs a per-chipset bundle and
an embedded-SDK app, not a config change; the HolmesGPT/K8sGPT/Kubernaut/Robusta competitor claim
is unverified.

**The one sentence to add to HARDWARE_UTILIZATION.md:** *Verify on Day 1, before anything else:
does `geniex serve` accept a ≥64K-context configuration Hermes will boot against, and does it
execute an OpenAI tool call end-to-end on the NPU bundle?* Both halves are currently assumed, and
both are where the evidence is thinnest.
